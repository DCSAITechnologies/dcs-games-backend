# DCS Games — header, navigation and backend-wiring closure, 8 September 2026

Triggered by a founder inspection of the public site: *"Login wraps into two
lines, Create With AI is oversized, Play is oversized, header controls are
vertically misaligned, spacing is inconsistent, overall desktop header looks
unfinished."*

Everything below was measured against the staging preview and the staging
Railway backend. Production was not touched.

---

## A. The header defect, and its root cause

**Reproduced before any change**, on the live public site and on staging, at
every desktop width from 960px to 1600px:

```
1600px  header=67   heights 71/94/71/34   wrapped: "Log in"x2  "Create With AI"x3  "Play"x2
1180px  header=67   heights 71/116/71/34  wrapped: "Log in"x2  "Create With AI"x4  "Play"x2
 900px  header=67   heights 49/49/49/34   wrapped: none
```

Three buttons, each **taller than the 67px header containing them**, each with
its label broken across two to four lines, spilling above and below the bar.

**Root cause — a space contest, not a button style.** `.nav-right` could shrink
(`flex-shrink` defaults to 1) and its buttons could wrap (`white-space` defaults
to `normal`), so the eight nav links took the available room and the action
buttons were squeezed narrower than their own text. Below 900px `.navlinks` was
`display:none`, the contest disappeared, and the same buttons rendered 49px and
single-line.

**The responsive path was correct and the desktop path was broken** — the
opposite of the usual story, and the reason this survived a mobile-first sweep.

One further discovery that mattered more than the styling: the fix initially went
into `assets/dcsgames.css`, and the header did not change. `index.html` does not
load that stylesheet at all — its styles are an inline `<style>` block that
mirrors the file. The estate has **three** headers: `index.html`'s own,
`site-chrome.js` for the games-* pages, and the dashboard shell in
`player-chrome.js`.

### After

```
1600 / 1440 / 1280px   full nav, no menu, controls 40x40, one line, centres identical, no overflow
1180 / 1024 /  834px   menu control, all four actions still fit, no overflow
        390px          menu + Play, scrollWidth 390 = viewport, nothing clipped
```

## G. Backend wiring defects found and fixed

1. **Fourteen genre pages rendered placeholder worlds while the real feed sat
   unused.** `GET /v3/discover?genre=<slug>` has filtered by genre the whole
   time, is public, and is already the feed Explore uses. The pages rendered
   `SEED.worlds` instead, so a genre with nothing published showed invented
   worlds *and* a genre with real ones never showed them — Adventure and Fantasy
   each have published worlds on staging that no genre page had ever displayed.
   Now wired, with the honest empty state when a genre is genuinely empty, and
   the reason corrected: an empty genre query means "nothing in this genre", not
   "nothing has been published".

2. **The rewards page described an economy that does not exist and stated a
   number the server contradicts.** It advertised "Season 4: Frostfall", a
   100-tier battle pass, daily claims, redeem codes, and "184 achievements to
   unlock". `GET /me/achievements` says there are **eleven**, six unlocked;
   `GET /me/streak` says, in its own words, *"A streak is a record of days
   played. There is nothing to claim, and no reward attached."* Achievements and
   the streak are now read from the server; everything else is named as not
   built.

3. **Community's "Top Crews" was a ranking with no backend to rank against.**
   `/social/teams` and `/social/orgs` return the *caller's own* teams and are
   authenticated — a different question from "who is top". The section now says
   so.

4. **`beta-lock.js` hot-linked a logo from production** (`https://dcsai.ai/brand/logo-mark.png`),
   so three staging pages fetched an asset from a production host. Vendored.

5. **`loadProfile` cleared the cached identity on any non-OK response** — true
   of 500, 502, 503 and 504 exactly as of 401 — so one upstream blip made the
   account menu report it did not know who the visitor was. Only 401 and 403
   clear it now. *(This was the P3 carried open from the 7 Sep report.)*

6. **A world could be lost because a model wrote "overcast" instead of
   "cloudy".** `src/v3/router/assembly.mjs` took `plan.environment?.weather`
   unvalidated, two lines below a `maturity` field that *is* checked against its
   enum. An unrecognised word failed WorldManifestV3 and the whole generation
   returned `server_error`. The schema keeps its eight values; assembly now
   normalises onto them.

   This also explains the intermittent **41/42** recorded as *unreproduced* in
   the 7 Sep report. It was two different things wearing one number: this, and
   an expired `OTHER_JWT` where the suite correctly refused to report an
   ownership-isolation check it could not perform rather than passing it
   vacuously. With a fresh token and the fix deployed: **42/42, three
   consecutive runs.**

### Accessibility regressions introduced by my own header fix

Stated plainly, because all three were caught by suites that already existed:

| regression | rule | fix |
| --- | --- | --- |
| brand 122x24 and buttons 69x36 on V3 pages | WCAG 2.5.5 — 44px targets at 320px | controls grow on phones; brand collapses to its orb keeping its accessible name |
| public header laid out 324px inside 320px | WCAG 1.4.10 reflow | the gaps absorb it, not the targets |
| brand edge 1:1, buttons 1.51:1 | WCAG 1.4.11 — a findable 3:1 edge | used `--edge` (the boundary token) instead of `--border` (the divider that "never has to be found") |
| focus ring clipped by `overflow:hidden` | visible focus | the clipping container is gone; ring is the estate's `--focus` at 3px |
