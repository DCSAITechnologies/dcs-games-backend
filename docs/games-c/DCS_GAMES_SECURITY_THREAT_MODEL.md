# DCS Games — GAMES-C security threat model

Owner: GAMES-C agent 6 (guard/QA). Date: 28 Sep 2026. Code: `src/v3/gamesc/guard/`. Tests: `test/gamesc-guard.test.mjs` (29 tests, each threat class has at least one attack-refused and one legitimate-accepted case).

Status labels: **PROVEN** = the control exists and a test shows it working. **PARTIAL** = the control is proven but not yet called from the live request path. **DESIGN-ONLY** = proposed, not applied. Nothing in `guard/` is wired into `server.mts` yet. The lead does that wiring (see "Integration" at the end), so every control below is PARTIAL in production until then.

Single entry point for manifests: `guardManifest(manifest, {allowHosts?, requirePins?=true})` → `{ok, blocking[], advisory[], by_threat}`. Every finding names its threat class.

| 1 | **Generated code** (Elevation, Tampering) | A provider, the companion or a user puts executable code into a manifest or patch (`behaviors[].script`, `onClick: "() => …"`, a function value), and the runtime `eval`s it | Policy: **no generated code is ever executed**. The runtime reads data-only manifests with a closed `BEHAVIOR_KINDS` set. `assertDataOnly()` refuses populated code-named keys (`script`, `code`, `js`, `eval`, `handler_code`, `wasm`, `glsl`…), function/arrow-shaped strings and non-JSON values. | 2 | **Malicious prompt** (Tampering, Info disclosure) | A user prompt attempts a jailbreak ("ignore previous instructions"), smuggles markup, pastes a credential, or is huge | `guardUserPrompt()`: NFKC normalisation, strips control/bidi characters, 4000-char cap, flags `ignore_previous`/`role_hijack`/`role_marker`/`exfiltration`/`tool_call` and markup. The real defence is structural: model output never executes and must pass the #7 schema. Companion `safety.mjs` (agent 1) has its own screen, and the two should be merged |
| 3 | **Unsafe URL** (Spoofing, SSRF, Info disclosure) | `javascript:`, `data:text/html`, SVG data, `file:`, `blob:`, `http:`, IP literals (all numeric spellings), `localhost`, private ranges, `169.254.169.254` metadata, punycode lookalikes, `user:pw@`, non-443 ports, `evil.com` suffix tricks | `checkAssetUrl()` is an **allowlist**: https only, and only on allowlisted hosts (`games.dcsai.ai`, `api.games.dcsai.ai`, `assets.dcsai.ai` (proposed), `cdnjs.cloudflare.com`, overridable via `DCS_ASSET_HOSTS`). | 5 | **Script injection** (Tampering, XSS) | `<script>`, `onerror=`, `javascript:`, `<iframe/svg/img>`, `eval(`, `new Function(`, `${…}` / `{{…}}` / `<%…%>` templates, `__proto__` keys in titles, NPC lines, UI text | `scanForInjection()` walks every string and key. `guardManifest` **blocks** on script tags, `javascript:`, event handlers, eval, Function and prototype pollution, and keeps template and dangerous-tag hits as advisory. `sanitizeText()` (NFKC, strips control/bidi, HTML-escapes `& < > " ' \` =`, neutralises `${`/`{{`, caps length) is the one display sanitiser. `sanitizeDeep()` drops forbidden keys | `guard/injection.mjs` | `injection: hostile strings flagged…`, `injection: __proto__ key flagged`, `injection: sanitizeText…` | PROVEN (guard). **Display path not wired**: the frontend must use `textContent` or this sanitiser | The frontend (`dcs-games-LIVE`) was not audited for `innerHTML` use in this lane. |
| 6 | **Remote asset substitution** (Tampering) | Bytes behind an allowlisted URL change after review (CDN or bucket overwrite, vendor reusing an id) | Content-hash pinning. ## Sandbox rules for the play page (DESIGN-ONLY: proposals, not deployed)

- **No eval anywhere in the runtime.** `script-src 'self' https://cdnjs.cloudflare.com` has no `'unsafe-eval'`. Add SRI to the three.js `<script>` tag.
- Proposed CSP (`cspHeader()` output): `default-src 'self'; script-src 'self' https://cdnjs.cloudflare.com; style-src 'self' 'unsafe-inline'; img-src 'self' data: https://games.dcsai.ai https://assets.dcsai.ai; media-src 'self' data: https://assets.dcsai.ai; connect-src 'self' https://api.games.dcsai.ai wss://api.games.dcsai.ai https://assets.dcsai.ai; worker-src 'self' blob:; object-src 'none'; base-uri 'none'; frame-ancestors 'self'; form-action 'self'`. Inline `<script>` blocks in play-v3.html (for example `window.__rt = runtime`) would need nonces or moving to a file before this can ship.
- Embedded published previews (UGC): `<iframe sandbox="allow-scripts allow-pointer-lock" allow="fullscreen; gamepad">`. Never combine `allow-scripts` with `allow-same-origin`. `checkIframeSandbox()` enforces this.
- The runtime consumes **data-only manifests**. Behaviours are a closed enum interpreted by `dcs-runtime.js`, and user or model text reaches the DOM only through `textContent` or `sanitizeText`.

## Integration (for the lead; exact proposals)

1. `src/v3/manifest/schema.mjs:181`: refuse `script`:
   `- if (!isObj(b.spec) && !isStr(b.script)) iss.err(\`${p}.spec\`, "a behavior needs a declarative spec or a script");`
   `+ if (!isObj(b.spec)) iss.err(\`${p}.spec\`, "a behavior needs a declarative spec");`
   `+ if (b.script !== undefined && b.script !== null) iss.err(\`${p}.script\`, "executable scripts are not permitted; use a declarative spec");`
2. `server.mts`: call `guardManifest()` before every world save or publish, and reject with 422 on `!ok`. Call `guardUserPrompt()` on `/v3/*/companion` and generate inputs.
3. Provider lanes (`src/v3/providers/text.mjs`, `media.mjs`, `asset3d.mjs`): wrap each paid `generate()` in `ledger.guarded({category, estimate:{price, …}}, fn)`, and persist the ledger per world.
4. Move `SECRET_RULES` + `BENIGN` out of `scripts/secret-scan.mjs` into `src/core/secret-rules.mjs`, then import it from the script, `publish/guards.mjs` and `guard/secrets.mjs`.
5. Netcode: call `checkPayload` + `createTokenBucket.take(sessionId)` per message and `createConnectionLimiter.admit` on upgrade.
6. Frontend `_headers`: ship the CSP above after inline-script nonces are in place.
