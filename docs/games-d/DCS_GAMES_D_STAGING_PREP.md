## 1. DCS_GAMES_ENGINE_EXTERNAL = 0, enforced

Before tonight the flag did not exist in any Games lane (A, B, C, D). It now
lives in `src/gamesd/engine-flags.mjs`:

- Unset, `""` or `"0"`: off.
- Any other value: recorded as a **request** and **refused**. The build stays
  local (fail-closed) and the refusal is returned in `result.notes` and
  `result.engine_external`.
- `enabled` is hard-coded `false`. `ENGINE_EXTERNAL_APPROVED = false` is a
  constant, so the flag can't be turned on by environment. Turning it on needs a
  code change behind a founder GO, in the same change that wires a capped route.
- `buildFromRecipe()` reads the env only for this flag. Every stage still gets
  `OFFLINE_ENV` (`DCS_PROVIDERS_OFFLINE=1`).
- The package bytes don't depend on the flag: builds with it set to `0` and to
  `1` have the same `integrity.sha256` (tested).

**Scope limit.** The flag governs the Games-D engine only. `server.mts` doesn't
import `gamesb` or `gamesd`. Its existing v3 generation routes read
`process.env` and go offline only when `DCS_PROVIDERS_OFFLINE=1` (or
`NODE_ENV=test`). **On staging, `DCS_PROVIDERS_OFFLINE=1` is the server-wide
kill switch.** `DCS_GAMES_ENGINE_EXTERNAL=0` alone doesn't stop those routes.

## 2. Outbound trap: zero external calls

`src/gamesd/quality/outbound-trap.mjs` replaces 24 outbound routes while a build
runs:

- `fetch` and `WebSocket`
- http, https and http2
- net and tls sockets
- dgram
- DNS (callback and promise forms)
- child_process spawn, exec and fork, including the sync forms (these are how a
  process could shell out to curl)

Each call is recorded and refused. `syncBuiltinESMExports()` makes sure named
imports of builtins (for example `import { request } from "node:https"`) are
trapped too.

`test/gamesd-outbound-trap.test.mjs` (5 tests, all pass):

| test | result |
|---|---|
| Flag resolution: off by default; `1`, `true`, `yes`, `on` and `2` are refused | pass |
| Positive control: fetch, `https.request`, `net.connect`, `dns.lookup`, spawn and a named ESM `request` are all caught | pass |
| All 18 sample games built under a **hostile env**: fake CEREBRAS, TOGETHER, DEEPSEEK and KINIX keys, ASSET3D and SPATIAL URLs, `DCS_PROVIDERS_ONLINE=1`, `NODE_ENV=production`, `DCS_GAMES_ENGINE_EXTERNAL=1`, `DCS_PROVIDERS_OFFLINE` unset | **0 outbound calls**, 18/18 ok |
| Package bytes are independent of the flag | pass |
| Vacuity control: the same hostile env passed straight to Games-B `buildGame` (bypassing Games-D) **does** reach for `fetch`, and the trap records it | pass |

The last row shows the zero comes from Games-D forcing providers offline, not
from a trap that sees nothing.

**Browser runtime.** `games-b-runtime/play.html` loads Three.js r147 from
cdnjs. That is a free static file, not a model or provider call, but it is an
outbound request from the tester's browser. See §9 for the self-host option.

## 3. Provenance: provider = local_fallback

Every Games-D package now carries an add-only top-level `generation` block. It
is identical for every build, so determinism is kept:

```json
{ "provider": "local_fallback", "engine": "gamesd-1.0.0", "method": "procedural",
  "external_generation": false, "engine_external": false, "external_calls": 0, "cost_usd": 0,
  "note": "Built by the Games-D local fallback engine ... none was called." }
```

`buildFromRecipe()` also returns `provider: "local_fallback"`.

**Wording finding.** Stage provenance comes from the shared v3 `Lane`. In
offline mode its entries include `after_failed: ["cerebras:gpt-oss-120b"]`,
`["together"]` and `["external-3d"]`. Those adapters were **skipped** after
their status check reported UNAVAILABLE. They were never invoked, as the trap
proves. The field name reads as "tried and failed", so the `generation.note`
states the truth. I didn't rename the field, because `Lane` is shared
repo-wide. That is recorded as a follow-up in §10.

What the test checks for each of the 18 packages:

- Every stage provider matches `local[:*]` or `authored`.
- Every model is `deterministic`, `human`, `content-addressed` or null.
- Every `cost_usd` is 0.
- Every asset adapter is local.
- The v3 manifest's `provenance.generated_by` names only local providers.

## 7. Tester-account requirements

- Auth backed by Supabase (or `DCS_AUTH_SECRET`). Ephemeral auth is refused at
  boot unless `DCS_ALLOW_EPHEMERAL_AUTH=1`, and that must stay unset.
- A tester is granted `internal_tester` only when one of these holds:
  1. their principal id is in `DCS_INTERNAL_TESTERS` (recommended), or
  2. their **email is confirmed** by the identity provider and listed there
     (unconfirmed emails are refused; see `src/core/principal.mjs`), or
  3. they have server-set `app_metadata.roles: ["internal_tester"]`.
  `user_metadata.roles` is ignored.
- One account per tester, with no shared logins. Staging-only accounts, not
  prod accounts.
- Testers need a desktop browser with hardware WebGL. On software GL
  (SwiftShader) the bench measured about 3–9 fps, which is advisory. Mobile is
  untested for Games-D.
- Testers must be told that games are **procedurally generated with no AI
  model**, and that no payments, publishing or multiplayer are live.
- Open risks that limit who can be a tester, from earlier lanes: TEN-F-01 HIGH
  (approvals RBAC gap), R-Series TEN-10 and the live-grant check are still
  open, and netcode auth is still `mockTokenVerifier`. Keep tester scope to
  **founder and a named internal list only**.

  and all 36 PNGs (18 GPU, 18 CPU) come from run 2.
